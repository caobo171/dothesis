DoThesis architecture

A single-worker FastAPI process runs the LangGraph orchestrator in-process, talks to Postgres for state and Gemini for LLM calls. Everything you'll see in this doc lives in one Python process per request.

30-second summary

The chat → orchestrator → Postgres + Gemini spine is unchanged from the original design. What this session added is three new layers on top of it: a planning layer (artifact DAG, planner, intake, backfill), a set of HTTP endpoints that expose those layers, and a reliability layer (bounded_invoke) that wall-clock-caps every LLM call so a stalled Gemini request can never freeze a turn.

What "worker" means here

I kept saying "worker" — I mean the uvicorn child process that serves HTTP requests. When you run uvicorn --reload, there are two processes:

  • Parent (reloader) — watches files in --reload-dir, spawns/kills the child.
  • Child (worker) — actually serves HTTP. Holds the LangGraph orchestrator in-process. Every Gemini call you saw happens here, in the same thread that's serving the HTTP request.

No Celery, no Redis, no background queue. The only other Python process is the on-demand auto-draft subprocess (python -m orchestrator) that runs full M1→M5 generation out-of-band when you click the Auto-draft button.

A single "Hello" turn — the request flow

  1. Browser → POST /api/v1/threads/{tid}/messages with {"text": "Hello"}
  2. uvicorn worker's send_message handler:
    • Persists the user message to messages table
    • Reads checkpoint via graph.aget_state(config)
    • Calls graph.astream(input, config) — yields events as nodes execute
  3. LangGraph runs each node in the same worker process:
    • _seed — seeds context_store + mode (no LLM)
    • supervisor — picks current_module; cold-start skip for the nav classifier when no module has confirmed_at yet
    • M1 — calls _ask_next_question → bounded_invoke(self._get_llm(), prompt, max_seconds=12). This is the Gemini call (~2-3 s warm, up to 12 s pathological).
  4. Each node's output is wrapped in an AIMessage; the handler yields data: {"type":"token", ...} SSE lines back to the browser.
  5. Browser appends to chat, hides the thinking-dots spinner.

What's measurable now

Every bounded_invoke call logs at INFO:

LLM.invoke[supervisor.py:supervisor_node] start (cap=8s attempt=1 prompt_chars=187)
LLM.invoke[supervisor.py:supervisor_node] OK in 2.34s
LLM.invoke[base.py:_ask_next_question] start (cap=12s attempt=1 prompt_chars=421)
LLM.invoke[base.py:_ask_next_question] OK in 1.87s

So if something looks slow, you can read the uvicorn console and see exactly which call site cost what.

M5 Writing & Export agents/m5_writing.py m5_writing slice: 6 chapters + bibliography + docx/pdf S3 artifacts

All five inherit from ModuleAgent in agents/base.py. The base class has the shared clarification loop (step()) and every hot-path LLM call goes through self._bounded(prompt).

Planning layer (added this session)

The original spine routed strictly M1 → M2 → M3 → M4 → M5 via next_unconfirmed_module(). This session added a layer that lets the system start anywhere, backfill missing prerequisites, and assess pasted work — all without changing the original spine.

artifacts.py

Models the thesis as a directed dependency graph of artifacts (topic, literature, design, analysis, ch_intro, ch_methodology, …). Each artifact has:

  • depends_on — prerequisite artifacts
  • dod(slice) — Definition-of-Done validator

readiness(context_store) returns {key → done|ready|blocked} over the whole graph in pure Python.

planner.py

plan_next(cs, target=None) picks the next-best action from the DAG:

  • work — an artifact is ready; do it
  • backfill — the target is blocked; do this prerequisite first
  • already_done / done

The supervisor consults the planner only when state.target_artifact is set; default sequential flow is byte-for-byte unchanged.

intake.py

merge_import(cs, blob) seeds slices from a structured blob (tagged _source="imported").

assess_work(text, llm) LLM-classifies pasted free-form work (a draft, abstract, methodology section) into proposed slices — surfaced as a dry-run via POST /assess.

backfill.py

reconstruct_artifact(key, cs, llm) infers a skipped upstream artifact from the other slices that ARE done (e.g. infer design from a student's existing analysis + topic). Tagged _source="reconstructed" and gated behind dod_design_structural + user confirm.

Reliability layer — bounded_invoke

LangChain's timeout=N on ChatGoogleGenerativeAI is per-RPC, not wall-clock. Gemini's internal retries can stretch a single invoke() to minutes. This session wrapped every hot-path LLM call in bounded_invoke:

def bounded_invoke(llm, prompt, *, max_seconds=60, retries=1, backoff_s=1.0):
    """Wall-clock-bounded invoke via ThreadPoolExecutor + future.result(timeout=...)."""
    ...
    # On TimeoutError → raise BoundedInvokeTimeout (subclass of TimeoutError → Exception)
    # Caller's existing except-block catches it and falls back gracefully.
