# Domain vocabulary for the DoThesis blog content engine — a WHITELIST.
#
# One token or phrase per line, matched case-insensitively as a whole word or
# whole phrase against the harvest keyword. `#` starts a comment; blank lines
# are ignored.
#
# Why a whitelist at all. `exclusions.txt` is a blacklist, and a blacklist only
# knows the junk it has already met. The newest competitor in the harvest
# (trithuccongdong.net) is a thesis-writing service with a huge generic Q&A
# section, so it ranks for school maths, English-essay templates and finance
# exams. Chasing that with one regex per accident is a losing race: the harvest
# grows, the blacklist never catches up, and 368,000/month of `cách làm tài
# liệu` walks into the backlog. A whitelist inverts the burden — a harvest row
# earns a page only by naming something this product actually teaches.
#
# The rule `plan` applies to every harvest row: keep it only if it hits an axis
# unit display, or contains at least one entry below as a whole word/phrase.
# Everything else is written to `plan-rejected.tsv` for a human to skim.
# The blacklist still runs first, for rows that use domain words in a domain we
# do not serve (`đề thi cfa` is the finance exam, not confirmatory factor
# analysis).
#
# Matching is whole-word, so `tra` does not match `straight` and `ave` does not
# match `average`. Vietnamese is written syllable-by-syllable with spaces, so a
# whole-word match on a single syllable is loose by design; that is why the
# rejects file exists and why the blacklist keeps the last word.
#
# Every axis unit `display` is added to this vocabulary at load time rather than
# copied here. Copying 600 displays would go stale the first time an axis file
# changes, and the axis files are already the committed source of truth for what
# a unit is called.
