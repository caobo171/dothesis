# SEO working files

Everything here is input to the DoThesis blog content engine
(`api/app/blog/content/`) and to the two skills that drive it,
`.claude/skills/dothesis-blog-content` and
`.claude/skills/dothesis-content-pipeline`. Read the pipeline skill first; this
file only says what each artefact is and which command reads or writes it.

Design: `docs/superpowers/specs/2026-09-07-blog-content-engine-design.md`.

**Never hand-edit the harvest.** Add an exclusion regex instead, so the reason a
row was dropped stays in version control.

## Axis files

`docs/seo/topic-bank/axes/{axis}.tsv`, tab separated, with a header row:

| Column | Meaning |
|---|---|
| `unit` | ASCII slug key for the unit. Lowercase, diacritics stripped, `đ` becomes `d` |
| `display` | the phrase as a student would type it, lowercase, with diacritics |
| `templates` | semicolon-separated phrasing templates. `{unit}` and `{display}` are substituted |
| `category` | one of the nine category slugs |
| `archetype` | one of the ten archetypes in `dothesis-blog-content/references/structure.md` |
| `family` | the cluster this unit belongs to. Drives the family-aggregate gate rule and sibling selection |

## The pipeline, end to end

Every command runs through the arch wrapper from `api/`.

```bash
cd api

# 1. cross every axis unit with its templates -> candidates.tsv
./run.sh python -m app.blog.content.cli expand

# 2. measure. The probe is five known keywords and prints its cost; run it and
#    read the cost before any bulk call.
./run.sh python -m app.blog.content.cli gate --source dataforseo --probe
./run.sh python -m app.blog.content.cli gate --source dataforseo
#    or, with volumes measured elsewhere:
./run.sh python -m app.blog.content.cli gate --source tsv --file measured.tsv

# 3. merge harvest + gate survivors, cluster, assign siblings -> backlog.tsv
./run.sh python -m app.blog.content.cli plan

# 4. write. Start at five and read them.
./run.sh python -m app.blog.content.cli write \
    --backlog ../docs/seo/topic-bank/backlog.tsv \
    --out data/blog-seeds/vi/posts --limit 5

# 5. mechanical QA. Exit 0 required before publishing.
./run.sh python -m app.blog.content.cli qa data/blog-seeds/vi/posts
#    the same gate without the venv:
python3 ../.claude/skills/dothesis-content-pipeline/scripts/qa_seeds.py \
    data/blog-seeds/vi/posts

# 6. counts, volume totals, spend, shortfall against the 1,000 target
./run.sh python -m app.blog.content.cli report

# 7. publish (Package A's CLI)
./run.sh python -m app.blog.cli create --dir data/blog-seeds/vi/posts \
    --schedule-start 2026-09-09 --per-week 40
./run.sh python -m app.blog.cli export-index
```

## Credentials

`DATAFORSEO_LOGIN` and `DATAFORSEO_PASSWORD` for the gate, `OPENAI_API_KEY` for
the writer. All three live in the repo `.env` and are loaded with `python-dotenv`
from the repo root. Never print them, and never commit a file that contains them.

**Known state, 2026-09-08.** The DataForSEO credentials in `.env` authenticate
(the API answers, not a 401) but the account has **no balance**: the probe comes
back `HTTP 402`, body `status_code 40200, "Payment Required"`, `cost 0`. So no
bulk measurement can run until the account is topped up, and nothing was spent
finding this out. Until then the gate has two working paths: `--source tsv` with
volumes measured through OpenSEO, and the harvest, whose volumes are already
measured and committed. `plan` runs on the harvest alone today and yields about
200 rows.

`gate` prints the `cost` field of every DataForSEO response and a running total.
The Google Ads search-volume endpoint takes up to 1,000 keywords per request, so
the whole candidate set is a small number of calls. OpenSEO, at about 1.7 credits
a keyword, is the fallback for short lists.

## Seed output

`api/data/blog-seeds/vi/posts/NNNN-{slug}.json`, gitignored. The database is the
source of truth and `docs/blog-index.md` is the committed snapshot. Rejected
drafts land in `rejected/` beside them and are worth reading: three rejects
sharing a failure means the prompt is wrong, not the model.
