What a healthy run through M1–M5 looks like end-to-end, so you can spot where yours diverges.

1 · Graph topology

One supervisor in the middle, five module agents on the spokes. Each module owns one ContextStore slice; the supervisor only routes. interrupt_after pauses execution after each module emits its question, so the graph runs in one user turn = one supervisor → module hop.

One-word vague answers The LLM extracts what you wrote; "marketing" with no context becomes the literal value. Fine for field, fails for scope or objectives. Match the field's shape: scope = geographic+temporal boundary; objectives = "Measure X / Examine Y / Compare Z" statements.
Editing message in Studio Studio's Chat tab can't reliably resume interrupt_after graphs. Edits create new threads, not continuations. Use Graph tab → Submit with "As Node" cleared. Or just use localhost:3000.

6 · M2 → M3 → M4 → M5 in one breath

Same hub-and-spoke pattern — supervisor routes, each module owns its slice. Here's what to expect once M1 closes.

M2 — Literature Review

Four internal phases, all conversational:

  1. familiarize — "Have you uploaded papers? Skip / upload."
  2. research_state — agent drafts a summary of where the field stands (calls scout_citations tool).
  3. gap_analysis — list of candidate gaps, you confirm which ones to chase.
  4. reference_confirm — per-reference page-number verification.

Output: m2_literature = { research_state, research_gaps[], references[] } → supervisor routes to M3.

M3 — Research Design (paradigm-aware)

Field walk diverges based on paradigm (chosen first, default inferred from M1's research_type):

quantitative:  design → tool → conceptual_model → scale_items → sample_size → sampling
qualitative:   design → tool → themes → interview_guide → purposive_criteria → sample_size → sampling
mixed:         mixed_design_type → [quant flow] → [qual flow] → sample_size → sampling

Cards for tool / design / mixed_design_type are now LLM-generated dynamically — they adapt to your paradigm + RQ.

M4 — Data Analysis

Detects data type from the paste-text the user provides, generates an outline of analysis steps, runs each step, interprets results, and supports ad-hoc requests like "also run a t-test on age groups". Output: m4_analysis = { data_type, outline[], results{}, custom_analyses[] }.

M5 — Writing & Export

Composes chapters per-section (per Q-S3 brainstorm decision), validates draft + citations, formats per the requested style, compiles PDF, exports DOCX. Output lives in S3; the artifact URLs come back as m5_writing.export_artifacts.

7 · If you're stuck mid-M1 right now

1. Pull state via the inspector. See exactly what M1 has confirmed and what it's awaiting: 
api/.venv/bin/python inspect_thread.py --latest
Look for _awaiting_field in m1_topic — that's the field the agent is currently asking about. Your next message will be extracted as that field's value.
2. Use the trigger phrases. If the agent's question is unclear, type explain or ?. If you genuinely don't have a preference, type you decide or tùy bạn.
3. Use localhost:3000 — not Studio. Studio's Chat tab can't resume interrupt_after graphs reliably. The production UI handles the full conversation natively.
4. Start a fresh thread. Stale threads carry confused state across code changes. If you restarted dev.sh after a fix shipped, old threads still run the old M1 code path until they hit a new node.
5. Last resort — reset M1. If you need to clear M1 entirely (rare): hit POST /api/v1/projects/<id>/reset?module=M1 or just delete the project and start over. Faster than fighting a wedged thread.
